# 石刻浅刻线补拍灯位选择（Flask）

给石刻摄影师用的网页工具：从备选灯位里选出一盏，补拍浅刻线时让刻线与
底面的可区分度最大，同时保证全区预测灰度不溢出。

## 业务规则（与实现一一对应）

1. 上传 **4～8 张**已对齐的灰度 PNG 裁片：Pillow 模式 `L`、尺寸完全相同、
   每边至多 16 像素；每张填写三维照明向量，另填 **2～8 个**备选灯向量。
2. 在放大裁片上点选 **1～4 对**像素：每对依次为刻线像素、底面像素，
   两点必须不同。
3. 每个像素的反射向量 `r=(x,y,z)` 满足 **z≥0**，且对每张保留的原照 i：
   `|L_i · r − g_i| ≤ 2`（g 为实拍灰度）。
4. **全区共用同一个排除选择**：不排除任何照片，或至多排除一张被取消
   “可靠”标记的原照；标为可靠的照片必须保留。所有像素在某排除选择下
   同时可行时，该选择才是一个“可行解释”。
5. 备选灯合格条件：在**所有可行解释**下，全区每个像素的预测灰度
   `c · r`（取该像素可行域上的最小/最大值，跨解释取并集）都落在
   **[5, 250]**。
6. 每盏合格灯的**保证值**：所有可行解释、所有点对中，最小的
   （底面预测灰度最小值 − 刻线预测灰度最大值），即最差情况下
   底面仍比刻线亮多少。
7. 推荐保证值最大且**严格为正**的灯，并显示保证值；同分按输入顺序
   取首盏。
8. 更改可靠标记后自动重新求解；**原照无共同解释**与**无灯可用**分别
   给出提示，并撤下旧推荐。

### 阴影诊断（支架投影只压暗原照一角）

9. 在案例页选一张原照做**阴影诊断**。诊断时**全组原照都参与**，沿用
   上面的反射向量模型；每个像素有两种假设：
   * 非阴影：所有原照仍用 `|L_i · r − g_i| ≤ 2`；
   * 阴影：所选原照 s 改用**单边约束** `L_s · r ≥ g_s + 3`，其余原照
     仍用 ±2。
10. 若某像素两种假设都不可行 → **观测冲突**，不给掩膜、不能启用。
    否则在所有“阴影/非阴影”二值标签中，求**四邻接边界边数最少**的
    可行掩膜（掩膜＝被判为阴影的像素集合）。
11. 用一次 s-t **最小割（最大流）**求全部最优掩膜：源侧残量可达的像素
    在**每个**最优掩膜中都是阴影；能到达汇的像素在每个最优掩膜中都不是
    阴影；两者之外的像素**判定有分歧**。复杂度为一次最大流，**不枚举
    掩膜**。最短边界值即最小割值。
12. 页面上把所有最优掩膜都判为阴影的像素、以及判定有分歧的像素分别
    叠在所选原照上；无解时提示观测冲突并列出冲突像素。
13. **只有唯一最优掩膜才能启用**，每个案例同时**至多启用一张**。
14. 启用或撤销时，按当前点对与可靠标记**重新求解选灯**。选灯仍按原
    规则决定是否排除整张原照（启用掩膜不改变 `可靠` 语义）；照片保留
    时，其阴影像素改用上述单边约束。**求解出错时保留原设置与旧推荐**
    并提示错误。

## 求解方法（solver.py）

每个（像素, 排除选择）构成一个三维线性可行域（半空间交集 + z≥0），
全部 LP 由 **SciPy `linprog(method="highs")`** 求解：

* 可行性：零目标 LP 是否成功；
* 备选灯预测灰度区间：最小化/最大化 `c·r`，无界时端点记为 ±∞，
  据此判定 [5, 250] 合规性；
* 保证值：对每对点分别求底面最小值与刻线最大值，取最差差值。

LP 结果按（像素, 排除选择, 目标方向）惰性缓存，一次请求内复用。

阴影诊断按（像素, 阴影/非阴影）各解一次零目标 LP 判定可行性；随后用
`scipy.sparse.csgraph.maximum_flow` 求一次最小割，得到最短边界与全部
最优掩膜的交/差集。启用掩膜后，同一套 LP 缓存把所选原照在阴影像素上
的 ±2 约束替换为单边 `≥ g + 3`。

## 启动方式

### Docker Compose（交付方式）

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000
```

### 本地直接运行

```bash
pip install -r requirements.txt
python app.py        # 监听 0.0.0.0:8000
```

## 网页演示

打开首页后点击“载入演示数据”（或访问 `/demo`）：

* 4 张 4×4 灰度裁片（`demo/`，由 `demo/generate_demo.py` 按
  `g = L·r` 合成，含底面与两种方向的刻线像素）；
* 4 盏备选灯分别演示：①合格且保证值最高（推荐）②合格但保证值为负
  （不推荐）③预测灰度越过 [5,250]（不合格，并显示越界像素与区间）
  ④合格、正保证但低于①（验证排序）；
* 页面自动用建议点对求解并展示推荐横幅与逐灯判定表；
* 取消任一原照的“可靠”勾选即自动重算，可行解释、合格灯与推荐随之
  更新；无共同解释 / 无灯可用时显示对应横幅且不再出现推荐。

### 阴影诊断演示（`/demo?scene=shadow`）

5×5、4 张原照，第 1 张左上 2×2 被支架投影压暗 4 个灰度
（`demo/shadow_*.png`）：

1. 直接求解 → 原照**无共同解释**，推荐撤下；
2. 在“阴影诊断”里对第 1 张点“诊断阴影” → 最短边界 **4** 条边，
   所有最优掩膜都判为阴影的像素就是左上 2×2，**无分歧、唯一**；叠加图
   用蓝色标出该区域；
3. 点“启用该掩膜并重算选灯” → 第 1 盏灯被推荐（保证值约 43.81），
   结果区标注本次求解已启用掩膜；
4. 点“撤销当前掩膜并重算选灯” → 恢复无共同解释、推荐撤下。

## 自测

```bash
bash tests/run_all.sh
```

* `tests/test_solver.py`：LP 求解层（推荐、容差带、排除与可靠标记、
  z≥0、同分取首、负保证不推荐）；阴影诊断（最短边界、唯一/分歧、
  观测冲突、单边约束生效、掩膜只作用于所选原照、不影响排除规则）；
* `tests/test_app.py`：Flask 端到端（上传校验、求解、改标重算、
  两种撤下推荐的情形、无灯可用）；阴影诊断/启用/撤销、越界原照、
  不唯一与冲突拒绝、单案例至多一张掩膜、重算失败保留原设置；
* `tests/dom_test.js`：jsdom 真实 DOM 交互（自动求解、点选、
  同像素拒绝、改标重算、提示文案与推荐撤下；阴影诊断叠加、启用/
  撤销、唯一性/冲突时按钮隐藏）。

## 已知限制

* 案例保存在进程内存中（单用户工具定位），重启后需重新上传；
* 阴影诊断对每个像素各解 2 次 LP，16×16、8 张原照的极端规模在开发机
  上约 2.3 秒（诊断）+ 8.5 秒（启用后求解），页面为同步请求；
* 不做用户鉴权，请勿直接暴露到公网；生产部署请通过环境变量
  `SECRET_KEY` 注入密钥。
